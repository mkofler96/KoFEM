Cantilever beam from a STEP file

The cantilever again, but built the way you build a model in the app: import a STEP block, mesh it, fix one end face and load the other. The mesh is an unstructured Netgen mesh of tetrahedra rather than a hand-made grid. The model opens ready to solve, and after the solve the Results panel compares the tip deflection with the hand formula.

Analytical solution

Euler–Bernoulli beam theory assumes that cross-sections stay plane and perpendicular to the deformed axis, which neglects shear deformation. Take w(x) as the deflection, positive upwards, with the load P acting downwards at the tip. Equilibrium of the part beyond a section x gives the bending moment

M(x)=−P(L−x),

and the curvature is proportional to it:

EId2wdx2=M(x),I=bh312.

Integrating twice with the clamp conditions w(0)=0 and dwdx(0)=0 gives the deflection curve

w(x)=−Px26EI(3L−x),

and at the tip

δ=w(L)=−PL33EI.

For this beam I=8.3333×106 mm4 and δ=−1.9048 mm.

Timoshenko beam theory adds the shear deformation that Euler–Bernoulli leaves out. For a cantilever with a tip load it adds a second term,

δs=−PLκGA,κ=56,G=E2(1+ν),

which is 0.78 % of the bending term for this beam (span ten times the depth). A converged 3-D solid model should therefore deflect slightly more than PL3/(3EI).

Finite element model

MeshNetgen, 25 mm maximum element size: 2,991 quadratic 10-node tetrahedra (P2)
Unknowns5,532 nodes, 16,596 degrees of freedom
MaterialLinear elastic, isotropic
SolverKoFEM engine (MFEM), the WebAssembly build the app runs: engine-5ceb743373dd

Netgen meshes the block with a 25 mm maximum element size, about 4 elements across the section. The elements are quadratic: linear tetrahedra lock in bending even more than the linear hexahedra do. The support and the load are each one CAD face, picked with one click, so they stay on the model when you change the element size and mesh it again. The deflection is the mean uy of the loaded face, which is what the app's hand check reads.

Discussion

KoFEM's tip deflection differs from PL3/(3EI) by −0.04 %. The beam-theory value is not the whole story: the shear deformation it leaves out adds +0.78 %, so a converged solid model would deflect slightly more. Against the Timoshenko value the result differs by −0.81 %, which is what the mesh still leaves out at this element size.

The quadratic hexahedra on a coarse grid come out +1.84 %. Both show the same thing: in bending, second-order elements are accurate on meshes coarse enough to solve in a second.

Reproduce

In the app: open the model, then Studies → Static 1 → Run static solve, select the result plot and set Field to Uy. The Result summary shows Min Uy -1.904e+0 mm.

From a clone (Node.js 20+, bash, curl), this rebuilds the model and its figure:

git clone https://github.com/mkofler96/KoFEM.git && cd KoFEM
bash scripts/fetch-wasm-engine.sh
cd web && bun install && bun run examples:generate-cantilever
