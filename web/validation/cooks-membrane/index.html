Cook's membrane

Cook's membrane (1974) is a tapered panel, clamped on one edge and sheared on the other. It has no closed-form solution. The finite element literature uses it because it combines bending and shear on a mesh that cannot be rectangular, which exposes elements that lock or lose accuracy when distorted.

Analytical solution

The panel is the quadrilateral with corners (0, 0), (48, 44), (48, 60) and (0, 44), of unit thickness, with E=1 and ν=1/3. A total shear force F=1 is spread uniformly over the right edge, and the left edge is clamped. All quantities are dimensionless. The result compared is the vertical displacement of the top-right corner C.

Without an analytical solution, the reference is the converged value of very fine plane-stress meshes reported in the literature, about 23.9.

The panel behaves like a short, tapered cantilever: span 48, depth tapering from 44 to 16. Linear elements lock in its bending, as in the cantilever, and every element is skewed, so elements whose accuracy depends on rectangular shapes do poorly. Coarse meshes of simple elements land far below 23.9.

Finite element model

Mesh16 × 16 grid, 1 through t: 256 linear 8-node hexahedra (P1)
Unknowns578 nodes, 1,734 degrees of freedom
MaterialLinear elastic, isotropic
SolverKoFEM engine (MFEM), the same WebAssembly build the app runs: engine-bb451aa7afb6

KoFEM is a 3-D solver, so the panel is a slab of thickness t=1 with one element through the thickness, clamped over the whole x=0 face. The load F is split equally over the nodes of the x=48 face, and the result is the mean vertical displacement of the two nodes at C.

Mesh convergence: Cook's membrane

Both orders rise past the 23.9 reference under refinement, so the pass on the 16 × 16 CI mesh is a cancellation of errors; treat this case as a regression check until the reference is reconciled.

Discussion

On the 16 × 16 case mesh KoFEM gives 24.11, which differs from 23.9 by +0.89 %. The convergence study shows that this agreement is partly coincidence. Under refinement both linear and quadratic elements move past the reference, to 25.03 (linear, 64 × 64) and 25.52 (quadratic, 16 × 16), and they have not yet levelled off at a common value.

A converging discretisation of the same problem would approach one value from both element orders. So the 3-D model here is not yet the problem the 23.9 reference solves. Possible causes, not yet resolved, are the 3-D slab clamped over a face versus the 2-D plane-stress model, and the equal nodal split of the edge load, which also puts a nodal force on the measured corner. Until this is reconciled the case is a regression check: it catches a change in the solver's answer, but it is not evidence of accuracy.

Reproduce

From a clone (Node.js 20+, bash, curl), this solves the case with the same engine and prints its line:

git clone https://github.com/mkofler96/KoFEM.git && cd KoFEM
bash scripts/fetch-wasm-engine.sh
node examples/validation/run.mjs --case cooks-membrane
