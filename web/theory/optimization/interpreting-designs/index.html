Interpreting optimized designs

What does an optimized density field tell you, and what must you check before using it?

A SIMP run returns one density per element and the history of its iterations. That is a material layout for the chosen loads, supports, volume and filter radius. Turning it into a part is a separate engineering step, which this page explains.

Watching and cancelling a run

While the optimizer runs, the viewport draws the density of the design each iteration has just analysed, and the convergence plot adds that iteration’s compliance, volume fraction and, with a stress limit, the aggregated and maximum relaxed stress. The last streamed density is exactly the returned one.

Early iterations look gray and blurred: densities start uniform and move by at most the move limit per step. A shape that looks finished can still be reorganising, so judge the final result, not an early frame.

Cancel terminates the engine worker. The partial run and its live density are discarded; there is no best-so-far design. Changing any optimization setting also clears an existing result. A saved analysis file keeps the optimization settings but not the density result, so re-run to restore it.

Densities, gray elements and the threshold

A density between 0 and 1 is a numerical intermediate, not a manufacturable porous material. Penalization and filtering push most elements towards 0 or 1, but gray elements remain along member boundaries, in a band whose width is set mainly by the filter radius.

The Results view hides elements below a threshold (default ρ≥​0.5). The element view draws the boundary of the kept elements, which shows exactly what was analysed but makes curved members stair-stepped. The smooth view averages densities to the nodes, weighted by element volume, and draws the surface where that nodal field equals the threshold. Both are interpretations of the same result.

The volume shown at a threshold is not the optimizer’s volume fraction. Raising the threshold removes gray material and can disconnect thin members; lowering it adds material. Choose a threshold where the load paths stay connected and the kept volume is close to the budget, and record that choice with the result.

Exporting the shape

Export shape as STL writes the surface currently shown — element or smooth — at the current threshold, in the model’s length units; STL itself carries no units. Kept solid elements export as the closed outward boundary of the kept set. Kept shell facets export as zero-thickness mid-surface triangles: their thickness is lost and must be restored when the part is rebuilt.

The STL is a mesh of triangles, not a CAD solid. It has the discretisation’s staircase or isosurface character, contains no design intent such as fillets or holes for fasteners, and is not re-imported into the model automatically. Treat it as a guide for redesign in CAD or as input to a mesh-repair and smoothing step.

Re-analyse before trusting a design

The optimizer’s compliance belongs to the density field with its Emin floor and penalized gray elements, not to the thresholded or redesigned part. KoFEM does not yet re-analyse the thresholded shape for you. To check a candidate design:

  1. Rebuild the shape as CAD, using the exported STL as a guide, and add the features the optimizer could not know about.
  2. Import it, mesh it as a solid (or idealise walls as shells), and apply the same materials, supports and loads.
  3. Run a static analysis. Compare stiffness with the optimizer’s compliance as a sanity check, then check displacement and stress against your requirements.
  4. Refine the mesh where stresses concentrate, as for any static study; see interpretation and convergence.

Expect the re-analysed compliance to differ from the optimized value. Thresholding removes gray stiffness, smoothing changes cross-sections and new features add or remove material. A large difference means the interpretation, not the optimizer, changed the structure.

Why convergence is not adequacy

A converged run meets the optimization problem it was given. The design can still be inadequate because that problem left things out:

  • One load case. The layout is stiff for the applied loads and may be weak for any other direction or combination.
  • Linear statics. There is no buckling, contact, large deformation, plasticity, fatigue or dynamics. Slender compression members found by a stiffness optimizer deserve a stability check.
  • Stiffness, not strength. Without a stress limit, peak stress is not controlled. With one, a relaxed element-centre aggregate is controlled, not the stress of the rebuilt part.
  • The design space and supports. Every element is a design variable, including those at supports and loads. Check that the interpreted shape still carries each load into each support.
  • Discretisation and filter. The minimum member size follows from rmin and the mesh; a different choice gives a different, locally optimal design.
  • Manufacturing. Overhangs, draft, minimum wall thickness and tool access are not constraints.

Physical adequacy is established by the re-analysis and by engineering checks, not by the optimizer’s convergence flag or volume fraction.
