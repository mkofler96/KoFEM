How does SIMP turn a solid FEM problem into a density optimization problem?

A static analysis answers “how does this part deform?”. Topology optimization asks a different question: “where should material be, inside a given design space, so the part is as stiff as possible for a given amount of it?”. SIMP (solid isotropic material with penalization) answers it by giving every finite element a material density and letting an optimizer adjust those densities, one linear-elastic analysis at a time.

One density per element

Mesh the whole design space once. Each element e gets a design density ρe between 0 (void) and 1 (solid material). It is a dimensionless fraction, not the mass density of the material. The mesh, supports and loads stay fixed for the whole run; only the element densities change.

Because ρe is constant over an element, the element is also the smallest feature the design can describe. KoFEM’s solid optimizer always uses linear (order 1) tetrahedra or hexahedra with one density per element, whatever order a static solve of the same model uses. The resulting shape is therefore a pattern of elements, not a CAD surface; interpreting optimized designs explains how to read and export it.

Penalized stiffness and its floor

The analysis needs a stiffness for every density. With full-material Young’s modulus E0, KoFEM uses the modified SIMP interpolation:

E(ρe)=Emin+ρep(E0−Emin),s(ρe)=E(ρe)E0=EminE0+ρep(1−EminE0).

The penalty p (default 3) makes intermediate density poor value: at ρe=​0.5 an element costs half its volume but provides only 0.53=​0.125 of its stiffness. A stiffness-seeking optimizer is therefore pushed towards 0 or 1. With p=​1, stiffness and volume are proportional and a gray “half-material” region is as good as solid and void; the worked example below shows this. KoFEM uses the power law as a numerical device for reaching a solid–void layout; a gray element is not a validated porous material.

The stiffness floor Emin/E0=​10−9 is fixed in the engine and is not a user input. Without it a void element would contribute zero stiffness, and a node surrounded by void would leave the global stiffness matrix singular. The floor keeps it positive definite for a supported model, at the price of very large stiffness contrasts that make the iterative solve harder.

Element stiffness is linear in E, so the full-material element matrix Ke0 is integrated once and only scaled afterwards:

K(ρ)=∑es(ρe)Ke0.

Assembly follows the same rules as a static solve; see assembly.

Objectives and constraints

Let d(ρ) solve K(ρ)d=​f for a fixed load vector f. The compliance is the work done by the load, twice the stored strain energy:

c(ρ)=fTd(ρ)=dTK(ρ)d.

Lower compliance means a stiffer structure under that load case. It is measured in work units (N·mm with N and mm). With element volume Ve, the material volume is V(ρ)=​∑eρeVe. KoFEM offers two formulations, both with ρmin≤​ρe≤​1:

minimum compliance:minρc(ρ)subject toV(ρ)≤vf∑eVe,
minimum volume:minρV(ρ)subject toc(ρ)≤callow.

The volume fraction vf is a fraction of the meshed design space. The compliance limit callow is in the model’s own work units, so it has no universal default. A minimum-volume run starts from full material; if even that design exceeds callow, the engine stops with an explicit error. Either formulation can also carry a maximum von Mises stress limit on all-solid models; stress-constrained runs change several details of the loop.

Both formulations need a load and at least one fixed support. The engine rejects non-zero prescribed displacements, for the reason given in the next section.

Compliance sensitivity without an extra solve

A gradient-based optimizer needs ∂c/∂ρe for every element. Differentiate the equilibrium equation with a design-independent load:

∂K∂ρed+K∂d∂ρe=0⇒∂c∂ρe=fT∂d∂ρe=−dT∂K∂ρed.

The last step uses fTK−1=​dT, valid because K is symmetric. Only element e depends on ρe, so with the element strain-energy measure qe=​deTKe0de:

∂c∂ρe=−s′(ρe)qe=−pρep−1(1−EminE0)qe≤0,∂V∂ρe=Ve.

The problem is self-adjoint: the displacement already solved for gives every sensitivity, with no second solve. Adding material never makes this structure more compliant. Two assumptions carry the result: the load does not depend on ρ, and supports hold d=​0. A non-zero prescribed displacement would make fTd differ from the strain-energy expression and need a separate adjoint, which KoFEM does not implement; it rejects such models rather than follow a wrong gradient. Body loads that scale with density, such as self-weight, are not part of the current formulation.

The solid loop solves every SIMP analysis with conjugate gradients to a relative residual of 10−8, tighter than the static solid solve. The sensitivity is quadratic in the displacement, so a loose solve would bias it.

Two bars sharing one load

Two parallel bars connect a fixed support to one loaded node, so they share the same extension u. Each has E0=​200000 MPa, area A=​5 mm2 and length L=​1000 mm, so its full-material stiffness is k0=​E0A/L=​1000 N/mm. The load is P=​100 N. The volume budget is one bar: ρ1+ρ2=​1. Then:

k(ρ)=k0[s(ρ1)+s(ρ2)],u=Pk,c=Pu,qe=k0u2,∂c∂ρe=−s′(ρe)qe.

p=​3, ρ=​(0.5,0.5)2500.440−120 each

p=​1, ρ=​(0.5,0.5)10000.110−10 each

For the gray design, s(0.5)=​0.125, so k=​1000(0.125+0.125)=​250 N/mm, u=​100/250=​0.4 mm and c=​100×0.4=​40 N·mm. Each bar’s qe=​1000×0.42=​160 N·mm and s′(0.5)=​3×0.52=​0.75, giving ∂c/∂ρe=​−0.75×160=​−120 N·mm.

With the penalty, putting all material into one bar is four times stiffer than splitting it. With p=​1 the split design is as stiff as the solid–void one, so nothing drives the optimizer to a crisp answer. The solid–void row also shows a weakness of the gradient: at ρe=​0, s′(0)=​0, so a void element receives no direct signal to return. Filtering spreads neighbouring information into it; see filtering. Every number above was checked by script, and each sensitivity was compared with a central finite difference of the compliance. That verifies the arithmetic and the sensitivity formula, not the production optimizer, which has its own finite-difference tests.

Solid, shell and coupled design domains

The app routes an optimization the same way as a static solve: by the element mix of the FEM discretisation. Each element in the model is a design variable; there is no separate design-space selection yet.

Design domains in KoFEM
ModelDesign variables and current rules
All solidOne density per tetrahedron or hexahedron, order 1. One design material: the run uses a single E and ν. Optional maximum-stress constraint. A separate level-set method is also available for minimum compliance; it is not described here.
All shellOne density per triangular shell facet. Element volume is facet area × thickness, so per-facet thickness is respected. One shell material. No stress constraint.
Mixed shell and solid, or any couplingOne density field over the tetrahedra followed by the facets. Couplings are geometric constraints, not design variables, and remain intact. One solid and one shell material, so their relative stiffness is kept. No stress constraint.

Bodies marked Shell must already be idealised into shell elements by re-meshing; the optimizer refuses to idealise them itself. The shell element and coupling mechanics are explained in shell formulation and solid–shell coupling. Supported and loaded elements are design variables too: the app does not yet pin any element solid or void. The engine already accepts such passive regions, but the app has no keep-in/keep-out picker yet.
